## 1. Overview

This workflow downloads a spatially and temporally subsetted GPM Dual-frequency Precipitation Radar (DPR) Level-2 dataset and checks the downloaded NetCDF files for possible read or data-chunk corruption.

The example requests one day of observations over a selected region and retrieves 15 variables from the **FS (Full Swath)** group. The same approach can be used to request other variables available in the selected GPM DPR collection.

The workflow involves three checks:

- **Download:** Retrieve the files generated by the subset request.
- **Download completeness:** Compare expected results with the files successfully downloaded.
- **File integrity:** Open each NetCDF file and attempt to read every dataset.

A file that downloads successfully may still fail when its contents are read. Similarly, a file that can be read is not automatically guaranteed to contain every expected observation.

## 2. Set up the Python environment

Create a dedicated Conda environment with Python 3.12. First, open a terminal and move to the folder where you want to keep the project and scripts.

```bash
cd /path/to/your/project
conda create -n gpm_dpr python=3.12 -y
conda activate gpm_dpr
python -m pip install --upgrade pip
python -m pip install harmony-py earthaccess h5py
```

The scripts use:

| Package | Purpose |
|---|---|
| `harmony-py` | Create and submit Harmony subset requests and retrieve job results |
| `earthaccess` | Authenticate with Earthdata and download result URLs |
| `h5py` | Open NetCDF/HDF5 files and read their datasets |
| `pathlib`, `datetime`, `netrc` | Python standard-library modules |

Whenever you open a new terminal, move to the project directory and activate the environment:

```bash
cd /path/to/your/project
conda activate gpm_dpr
```

Replace `/path/to/your/project` with your actual project directory. The environment only needs to be created once.

## 3. Configure Earthdata credentials with `.netrc`

The download workflow requires authentication with NASA Earthdata. Store your Earthdata Login credentials in a `.netrc` file in your home directory.

On Linux, create or edit `~/.netrc` and add:

```text
machine urs.earthdata.nasa.gov
login YOUR_EARTHDATA_USERNAME
password YOUR_EARTHDATA_PASSWORD
```

Replace the placeholders with your NASA Earthdata Login credentials. Then restrict access to the file:

```bash
chmod 600 ~/.netrc
```

Keep this file private. Do not upload it, commit it to a public Git repository, or include real credentials in shared code.

The existing-job download script reads credentials from `~/.netrc` to authenticate with Harmony. It also uses `earthaccess.login(strategy="netrc")` to authenticate Earthaccess.

## 4. Create and submit a GPM DPR subset request

The example uses the GPM DPR collection `C4054954501-GES_DISC`. It requests data for **1 June 2015 (UTC)** within the bounding box 64°E–100°E and 5°N–40°N.

The 15 selected variables are listed below. Latitude, longitude and scan-time information are deliberately included because they are essential for locating observations in space and time.

| Group | Selected variable names |
|---|---|
| `CSF` | `typePrecip` |
| Latitude / Longitude | `Latitude`, `Longitude` |
| `PRE` | `height`, `heightStormTop` |
| `SLV` | `paramDSD`, `precipRate`, `zFactorFinal` |
| `ScanTime` | `DayOfMonth`, `Year`, `Month`, `Hour`, `Minute`, `Second`, `DayOfYear` |

The variable paths use the form `FS/group/variable`. For example, `FS/SLV/precipRate` selects `precipRate` from the `SLV` group in the Full Swath.

Other groups and variables are also available in the DPR swath structure. The following are examples; availability should be checked against the product and collection version being requested.

| Group | Other variable names |
|---|---|
| `PRE` | `binClutterFreeBottom`, `binStormTop` |
| `CSF` | `heightBB` |
| `SLV` | `precipRateNearSurface`, `precipWaterIntegrated`, `precipRateESurface`, `phaseNearSurface`, `epsilon`, `zFactorCorrected` |
| `SRT` | `piaFinal`, `piaSRT` |
| `DSD` | `binNode` |
| `Experimental` | `sigmaZeroProfile`, `binDEML2`, `seaiceConcentration` |
| Other groups | `scanStatus`, `navigation`, `VER`, `FLG` |

You can replace or add variable paths in the `variables` list to request other fields. For example, a variable in the `SLV` group can be requested using `FS/SLV/precipRateNearSurface`. The same selection principle applies to other available swath groups, including `HS` where supported.

**Important:** Always retain latitude, longitude and scan-time variables when preparing subsets for spatial and temporal analysis.

**Save the following script as `01_submit_gpm_dpr_subset.py`.**

```python
from pathlib import Path
import datetime as dt

from harmony import Client, Collection, Request, BBox


# --------------------------------------------------
# 1. Collection and variables
# --------------------------------------------------

COLLECTION_ID = "C4054954501-GES_DISC"

variables = [
    "FS/CSF/typePrecip",
    "FS/Latitude",
    "FS/Longitude",
    "FS/PRE/height",
    "FS/PRE/heightStormTop",
    "FS/SLV/paramDSD",
    "FS/SLV/precipRate",
    "FS/SLV/zFactorFinal",
    "FS/ScanTime/DayOfMonth",
    "FS/ScanTime/Year",
    "FS/ScanTime/Month",
    "FS/ScanTime/Hour",
    "FS/ScanTime/Minute",
    "FS/ScanTime/Second",
    "FS/ScanTime/DayOfYear",
]

# --------------------------------------------------
# 2. Output directory
# --------------------------------------------------

output_dir = Path("./GPM_DPR_subset")
output_dir.mkdir(parents=True, exist_ok=True)


# --------------------------------------------------
# 3. Create the subset request
# --------------------------------------------------

request = Request(
    collection=Collection(id=COLLECTION_ID),

    # West, South, East, North
    spatial=BBox(64, 5, 100, 40),

    # Full day: 1 June 2015 (UTC)
    temporal={
        "start": dt.datetime(2015, 6, 1, 0, 0, 0),
        "stop": dt.datetime(2015, 6, 1, 23, 59, 59),
    },

    variables=variables,
    format="application/netcdf",
)


# --------------------------------------------------
# 4. Validate and submit the request
# --------------------------------------------------

if not request.is_valid():
    raise ValueError(request.error_messages())

print("Request validation successful!")

client = Client()
job_id = client.submit(request)

print("Harmony Job ID:", job_id)


# --------------------------------------------------
# 5. Monitor processing
# --------------------------------------------------

print("\nWaiting for Harmony processing...")

client.wait_for_processing(job_id, show_progress=True)

print("\nProcessing completed!")


# --------------------------------------------------
# 6. Check expected results and download
# --------------------------------------------------

expected_urls = list(client.result_urls(job_id))
print("Expected result files:", len(expected_urls))

download_futures = client.download_all(
    job_id,
    directory=str(output_dir),
    overwrite=True,
)

downloaded_files = []
download_errors = []

for index, future in enumerate(download_futures):
    try:
        downloaded_files.append(Path(future.result()))
    except Exception as exc:
        download_errors.append((index, str(exc)))


# --------------------------------------------------
# 7. Check download completeness
# --------------------------------------------------

existing_nonempty_files = [
    file for file in downloaded_files
    if file.is_file() and file.stat().st_size > 0
]

print("\n-----------------------------------")
print("DOWNLOAD REPORT")
print("-----------------------------------")
print("Expected result URLs       :", len(expected_urls))
print("Download tasks returned    :", len(download_futures))
print("Successfully returned files:", len(downloaded_files))
print("Existing, non-empty files  :", len(existing_nonempty_files))
print("Failed download tasks      :", len(download_errors))

if (
    len(expected_urls) == len(existing_nonempty_files)
    and not download_errors
):
    print("\nDownload count and file-existence checks passed.")
else:
    print("\nWARNING: Download results need attention.")

    if download_errors:
        print("\nFailed tasks:")
        for index, error in download_errors:
            print(f"Task {index}: {error}")

    print("\nFiles returned by the download operation:")
    for file in downloaded_files:
        print(file)
```

**Run the script** from the project directory after activating the Conda environment:

```bash
python 01_submit_gpm_dpr_subset.py
```

The subset files are saved in the `GPM_DPR_subset` directory.

The completeness check compares the number of result URLs with the returned paths that exist and are non-empty. It is a practical download check, not a checksum-based verification against the remote source.

## 5. Downloading results from an existing Harmony job

A subset request does not have to be submitted again if its Harmony job has already been created. When a Job ID is available, its result URLs can be retrieved and the files downloaded separately.

This is useful when subset processing has already completed or when the download needs to be performed again without rebuilding the original request.

**Save the following script as `02_download_existing_harmony_job.py`.**

```python
from harmony import Client
from harmony.config import Environment
import netrc
import earthaccess


def main(job_id="169a927c-d3a2-474d-bd5c-5ebf6ab512f4"):

    # Read Earthdata credentials from ~/.netrc
    credentials = netrc.netrc().authenticators(
        "urs.earthdata.nasa.gov"
    )

    if credentials is None:
        raise RuntimeError(
            "Earthdata credentials not found in ~/.netrc"
        )

    login, _account, password = credentials

    # Authenticate with Harmony
    harmony_client = Client(
        auth=(login, password),
        env=Environment.PROD
    )

    # Authenticate Earthaccess using ~/.netrc
    earthaccess.login(strategy="netrc")

    print("Getting subset job status:", job_id)

    job = harmony_client.status(job_id)

    if job["status"] not in ("successful", "complete_with_errors"):
        print("Waiting for the job to finish...")
        harmony_client.wait_for_processing(
            job_id,
            show_progress=True
        )

    # Retrieve result URLs from the existing job
    urls = list(harmony_client.result_urls(job_id))

    print("Number of result URLs:", len(urls))
    print("Downloading files using Earthaccess...")

    earthaccess.download(urls, f"./{job_id}")

    print(f"\nDownload finished. Check the directory: ./{job_id}")


if __name__ == "__main__":
    main()
```

**Run the script** from the project directory after activating the Conda environment:

```bash
python 02_download_existing_harmony_job.py
```

The script uses the Job ID in `main()`. Replace the example Job ID with your own existing Harmony Job ID. The downloaded files are saved in a directory named after that Job ID.

This approach retrieves the URLs associated with an existing job and passes them to Earthaccess for downloading. It is an alternative download route, not an additional step required after the first approach.

## 6. Checking the integrity of downloaded NetCDF files

After downloading, the next step is to check whether the files can be opened and whether their datasets can be read.

The script below checks every `.nc` file in the same directory as the Python script.

For each file, it:

1. Attempts to open the file with `h5py`.
2. Traverses the file to identify datasets.
3. Reads each complete dataset.
4. Marks the file as potentially corrupted if an exception occurs or no datasets are found.

Reading the datasets, rather than only opening the file, helps detect problems that may appear when the stored data or chunks are accessed.

**Save the following script as `03_check_dpr_files.py`.**

```python
import h5py
from pathlib import Path


# --------------------------------------------------
# 1. Directory containing this Python script
# --------------------------------------------------

folder = Path(__file__).resolve().parent

log_file = folder / "corrupted_files.log"
summary_file = folder / "file_check_summary.txt"

nc_files = sorted(
    file for file in folder.iterdir()
    if file.is_file() and file.suffix.lower() == ".nc"
)


# --------------------------------------------------
# 2. Check each NetCDF file
# --------------------------------------------------

total_files = len(nc_files)
corrupted = []
uncorrupted = 0

for file in nc_files:

    try:
        with h5py.File(file, "r") as ds:

            datasets_found = []

            def check_dataset(name, obj):
                if isinstance(obj, h5py.Dataset):
                    datasets_found.append(name)

                    # Read the complete dataset
                    _ = obj[...]

            ds.visititems(check_dataset)

            if not datasets_found:
                raise ValueError("No datasets found in file")

        uncorrupted += 1

    except Exception:
        corrupted.append(file.name)


# --------------------------------------------------
# 3. Write corrupted filenames to a log
# --------------------------------------------------

with open(log_file, "w", encoding="utf-8") as f:
    for filename in corrupted:
        f.write(filename + "\n")


# --------------------------------------------------
# 4. Write the summary report
# --------------------------------------------------

with open(summary_file, "w", encoding="utf-8") as f:

    f.write("GPM DPR NetCDF File Validation Summary\n")
    f.write("=" * 40 + "\n\n")

    f.write(f"Total number of files      : {total_files}\n")
    f.write(f"Total corrupted files      : {len(corrupted)}\n")
    f.write(f"Total uncorrupted files    : {uncorrupted}\n")

print("File validation completed.")
print("Corrupted file log:", log_file)
print("Summary report:", summary_file)
```

Place this script in the directory containing the `.nc` files you want to validate. Since the script checks the directory in which it is located, run it from that directory after activating the Conda environment.

For files downloaded using the first approach:

```bash
cd GPM_DPR_subset
conda activate gpm_dpr
python 03_check_dpr_files.py
```

For files downloaded through the existing-job approach, change into that job's download directory instead of `GPM_DPR_subset`. If needed, copy `03_check_dpr_files.py` into that directory before running it.

The script produces two reports:

- **`corrupted_files.log`** — filenames that failed the check.
- **`file_check_summary.txt`** — total, potentially corrupted and successfully read file counts.

## 7. What these checks establish

| Check | What it tells you |
|---|---|
| Download completeness | Whether the expected result count matches the returned, existing and non-empty files |
| File integrity | Whether the files can be opened and their datasets read without an exception |
| Scientific/data completeness | Whether all expected observations, variables and valid values are present |

The scripts above perform the first two checks. They do not independently prove scientific/data completeness, validate every observation against an external reference, or perform checksum verification.

A file classified as uncorrupted by this script should therefore be understood as a file that passed the implemented read test—not as a guarantee that every expected observation is present or scientifically valid.
